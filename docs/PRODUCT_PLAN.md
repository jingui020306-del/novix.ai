# novix.ai 产品需求与实施边界

稳定的产品事实以根目录 [PRODUCT.md](../PRODUCT.md) 为准；本文件保存需求分解、实施计划与研究建议，逐轮结果见 [改动记录](changes/README.md)。设计调整不能用新的外观决定覆盖已确认的产品事实。

当前源码的视觉 token、布局和组件记录见 [DESIGN.md](../DESIGN.md)，渲染预览补充在 `.impeccable/design.json`。它们描述本轮实际实现，不表示用户已经认可新版审美；检查覆盖与限制仍以轮次日志为准。

目标是让普通作者能完成“准备设定—写作—检查—修改—保存”，不需要先理解程序字段、模型路由或检索系统。AI 使用作者最新保存的材料；关系索引帮助选择材料，引用和事实核验仍然保留。

作者进一步明确的主流程是：**先理清大框架、人物交集、双方出招和节拍 → 作者确认 → 拆成场景与章节 → 生成正文 → 局部修改**。技法服务于这个流程，不要求作者先选择一长串技法才能开始。

用户结构化确认，打开应用优先看到“故事框架与场景安排，像编辑策划工作台”。该轮视觉工作保留功能、数据和设置页结构，完成后用户明确评价“改得很不错”。这只代表本轮视觉认可，检查覆盖与评审限制见 14:04 轮次日志。

本文区分用户需求与实施计划，不表示所有项目已经完成。实际修改、测试和遗留事项见 [改动记录](changes/README.md)。

## 一、前端：按作者的任务组织

| 作者要做的事 | 界面应提供什么 | 本轮范围 |
| --- | --- | --- |
| 开始使用 AI | 容易找到的模型设置、服务地址与密钥表单；清楚区分模拟预览、配置不完整、已经填写 | 中文化与入口整理 |
| 整理人物 | 每个人物有独立卡片；姓名、身份、外貌、动机、性格、成长经历、说话方式、底线、人物关系与标签分别编辑 | 普通表单与逐字段 AI 生成 |
| 维护世界观和文风 | 保留独立卡片；可手写、可让 AI 提建议，作者修改后保存 | 编辑与 AI 建议入口 |
| 写正文 | 当前章、连续多章、指定桥段、当前卷或已规划的整书；显示实际进度 | 范围选择与暂停、继续 |
| 找到伏笔与作品事实 | 从故事、章节或关系入口找到对应内容，能返回原文依据 | 理顺入口，增加有来源的基础关系视图 |
| 修顺文字 | 日常润色和清晰自然改写；只显示修改后的文字，可预览后应用或保留原文 | 独立按钮与确认流程 |
| 按需要选技法 | 点击抒情表现、结构、叙事等分类后，列表实际筛选；当前分类清楚可见 | 下一轮接通筛选与使用反馈 |
| 看懂可信检查 | 默认先看需要处理的结果，再展开中文证据与原文；工程细节按需查看 | 下一轮简化默认展示 |
| 分任务选择模型 | 人物、正文、审查、润色等任务可分别选模型；保留配置能力，避免堆叠内部路由 | 下一轮整理任务分配界面 |

界面原则：

- 默认显示“人物、章节、伏笔、模型”等作者用语；ID、type、payload、路由、文件路径和 JSON 不占据日常表单。
- 让主要入口有可见中文名称；常用动作靠近当前内容，技术详情按需展开。
- 单个字段点击 AI 生成后先填入表单，作者仍可修改；点击保存才成为后续使用的作者版本。
- 保留现有世界观检索、文风样本分析、事实核验、修改确认及必要高级配置。
- 沿用现有组件和视觉基础，优先解决层级、文案、布局与状态反馈，不增加装饰性的 AI 仪表盘。
- 本轮应用已安装的 `frontend-design`、`impeccable` 和 `ponytail` 技能；技能安装不等同于业务功能完成。
- 故事和导航继续按作者任务改善层级与布局；点击分类、结果和入口应有实际作用，不能仅改变外观或停留在标签状态。
- 技法可以作为场景中的可选建议与后台写作规则，不前置成大量必填选项；现有技法数据和高级使用方式继续保留。

## 二、后端：有来源的关系与按章取材

### 资料的权威边界

- `cards/` 保存作者确认的静态设定，包括人物、世界观、文风和大纲。后续调用读取最新保存内容，不让旧缓存、旧草案或启动演示初始化覆盖它。
- `canon/` 继续保存动态事实、冲突和时间线，保持追加记录。新增关系索引不能成为另一个互相冲突的事实库。
- AI 生成的字段或整张草案仍是建议；保存或确认以后才成为作者材料。
- 保留版本快照和修改日志用于追溯，不自动回滚作者已经保存的修改，也不擅自清理历史数据。

### Obsidian 式的关系模式

以现有人物卡、事件、章节、世界规则和伏笔为节点，使用有类型、可追溯的关系连接它们，例如“认识”“发生于”“在本章埋下”“在后章回收”。作者可查看出链和反链；AI 可以沿同一关系找到相关材料。

每条关系应能说明来源：作者显式填写的关系、对应文件，或正文证据位置。自动推断、未经确认的关联必须与已确认关系区分，不能因为图上有箭头就当成事实。

第一步复用现有文件与轻量索引，不增加图数据库或第二套项目目录。真实 Obsidian 连接、双向同步，以及 `[[链接]]`、块引用或嵌入格式的导入导出，属于后续兼容能力，不能写成已经接通。

### 按当前或过去章节检索

建议的材料选择过程：

1. 以当前章节、作者要求、出场人物和章节计划作为检索入口。
2. 选择相关人物、世界规则、文风约束、未回收伏笔，以及必要的当前和过去章节摘要。
3. 通过相关节点的有限邻接关系补充必要材料；保留来源和原文证据，需要核验时再取原文片段。
4. 结合已有检索结果与上下文预算，记录实际使用和裁剪了哪些材料，而不是每次重发整本书。
5. 作者保存修改后，用内容变化使相关索引或摘要失效，后续请求应读取最新版本。

时间边界尤其重要：区分“作者知道”“读者已经知道”“这个人物此时知道”。过去章节的审查不能把后续揭示当作人物当时已经掌握的信息；规划中的伏笔与正文中已发生的事实也不能混为一谈。

关系图可帮助减少重复输入，但实际 token 消耗必须通过真实请求记录比较，不能承诺固定节省比例。它也不能单独保证无幻觉或无人物 OOC；引用、事实核验和作者确认不能取消。

### AI 生成与长任务控制

- 整张卡片和单字段生成复用已有模型配置，读取最新材料；调用失败明确显示，不拿固定模板冒充成功的 AI 结果。
- 章节或桥段作为可保存进度的单元。暂停在当前单元结束后生效，继续时跳过已完成单元。
- 服务重启后保留断点；尚未完成的单元可以显式重试，不宣称能够恢复第三方模型已经断开的流式连接。
- 整书范围以已经创建或明确列入计划的章节为准，不凭空承诺任意长度的一次生成。
- 润色检查病句、搭配、标点、缺失主语与指代，保留语义和语气；改写遵循作者的场景与修辞要求。
- 修改预览不覆盖正文；应用前核对原文是否已变化，应用后保留补丁操作、统一差异和快照。

### 拉片式参考转为小说叙述

拉片式理解应是每次生成时默认使用的后台写作能力，而不是要求作者先填写摄影术语。它关注景别与注意焦点、布景与氛围、无台词时的动作、环境如何传达情绪，以及人物动机如何驱动动作和对话。

作者也可以补充参考镜头、布景、人物动机、动作和表演信息。后端把这些内容转成动作、感官、节奏、视角与人物心理相互衔接的小说叙述，而不是输出摄影脚本或分镜表。本轮正在落实默认的 `scene_direction` 写作指导；默认规则不能冒充作者已经确认的新剧情。

这些材料与既有关系和章节上下文一起进入当前写作请求，不为每一个段落另增加一次规划模型调用。参考信息仍需来源与边界，不能把参考中的人物设定或事件不加确认地写成当前作品事实。

### 故事表格与十五拍：后续方案

用户所说的“15派”，结合开场画面、阐明主题、铺垫、触发和争论这些例子，理解为 **Save the Cat 十五拍**。建议把它作为整本书的结构参考，不把每一章强塞成十五拍；小说结构参考见 [Jessica Brody 的小说十五拍入门资料](https://www.jessicabrody.com/wp-content/uploads/2020/01/Save_the_Cat_Writes_a_Novel_Starter_Kit_v6.pdf)。

后续可用三个彼此关联的视图帮助作者整理材料：

| 建议视图 | 主要内容 | 作者要解决的问题 |
| --- | --- | --- |
| 故事骨架 | 情势、人物线、主要转折、节拍 | 故事为什么这样推进，人物何时相遇与改变 |
| 场景交锋 | 目标、双方出招、阻碍、动作、结果 | 这一场谁想要什么，如何互相影响，结果改变了什么 |
| 画面情绪 | 注意焦点、微动作、环境、情绪变化、伏笔 | 不靠解释和台词时，读者具体看见与感受到什么 |

场景可以借助目标、冲突、结果与人物后续反应、选择来检查因果，不必把所有格子机械填满；参考 [K. M. Weiland 的场景组织说明](https://www.helpingwritersbecomeauthors.com/how-to-write-scenes/)。景别、布景、身体表现和光线等分析维度，可参考 [Film Education 的电影术语说明](https://www.filmeducation.org.uk/resources/secondary/teaching_with_film/film_in_the_classroom/terminology/)，使用时转成小说叙述和作者可理解的描述。

以上三个关联视图仍是研究建议。此后用户另行明确选择本轮实现五张应用内关联策划表并支持导出，具体范围见下文；它不等于引入重型表格编辑器或完整的三个视图系统。

### 请求、阶段和模型的 token 用量

- 记录每次模型请求，并能按写作阶段和模型汇总输入、输出及总 token。
- 优先记录服务商实际返回的用量；服务商未提供时，显式标记为估算，不能把字符串长度换算当作实测。
- 失败、重试、回退和模拟请求的归属应可辨认，避免同一请求重复累计或把模拟成本混作真实调用成本。
- 用量记录应保留必要的模型、任务和时间关联，不记录密钥或完整敏感请求。
- 接口和字段以实际落地实现为准，在对应轮次日志中登记。展示“本次用了多少”不等于证明“已经省了多少”；真实节省效果仍需同条件的真实请求比较。

## 四、讨论结论与本轮范围

用户要求先讨论细节，再并行实现。当前讨论项为：长文本拆解并自动补充规划表，空白内容由作者或 AI 补充；统一各入口占位技法的隐藏；改写风格与氛围；卡片关系与场景、世界、事实的串联；全局策划到本章目标和正文的衔接，减少重复共识；长篇增量摘要、事件索引与按需回查。

已进入本轮范围的包括技法调用链、增量更新时机，以及用户后续明确确认的五张关联策划表和导出。其他仍待细化的模块不据此一并实现；视觉认可也不延伸为其他功能的实施授权。

### 已明确的讨论结论

- 长描述中的确定内容直接提取，补充建议单列待确认。
- 十五拍是可选整书模板，章节和场景灵活拆分。
- 文字风格与情绪氛围分开选择，均可自定义。
- 作者明确写出并保存的关系自动连线；AI 推测待确认。

章前共识方面，用户要求主 agent 给建议，当前建议为“策划维护本章目标，正文读取目标，并提供一个可选临时补充框”；尚待完整拆分讨论，不能写成用户已最终确认。其余六模块细节继续讨论。

### 本轮已明确的两项范围

- 技法必须能用于具体章节或文章、故事概括和人物设定，并将选中技法的最新保存内容送入对应 AI，不停留在独立参考库。
- 用户已确认增量时机：保存时标记变化，不触发模型；下一次生成前只更新受影响的摘要与索引，复用未变化材料。派生材料不取代作者原文与设定的权威性，不自动回滚作者内容。

实施理由、保护边界、最终契约和验收证据见 [14:44 轮次](changes/2026-11-13_14-44.md)。本轮两条调用链及后续明确增加的独立五表已完成，不据此宣称其他讨论模块都已完成。

### 用户后续明确增加：五张关联策划表与导出

参考来自用户截图及[小红书笔记](https://xhslink.cn/o/6aaYYWbY1jZ)，主 agent 已实际浏览，用户问答确认需要应用内表格并支持导出。

- 五张表为：情节梗概、角色交集、人物故事线、十五节拍表、十五节拍简表。
- 用户后续明确否定复用或改写原故事 `important_scenes` 的方案。最终使用独立入口“情节工作表”及 `cards/outline_planning_<storyId>.yaml`，以 `payload.story_card_id` 关联原故事；该 outline 卡内四表为 `important_scenes`、`character_intersections`、`character_storylines`、`beat_sheet`，另有 `inspiration`、`planning_worksheet` 与 `beat_sheet_enabled`。原故事同名字段不回写，十五节拍简表与节拍表同源。

最新导航已由用户确认并接入：故事策划 → 情节工作表 → 人物与设定 → 事实与关系 → 章节正文 → 写作技法 → 模型与设置，默认故事策划。世界观可选字段为 `extra_context` 内 `map_url`、`oc_notes`、`races[]`、`genders[]`、`levels[]`，不重排已有设定；地图只提供已有URL预览，未实现上传或视觉识图。

### 15:33 讨论及后续授权

用户希望上述模块使用共享主记录和引用，做到改一处后相关视图联动。作者端需要左侧竖向目录、右侧详情，以及可切换的表格、地图、关系与时间线；后台需要有总预算、跨模块去重、带来源和章节知识边界的相关材料。世界观按 M. D. Presley 六方向可选扩展，不把未设定内容自动编造为事实。
