## 13:50 追加：主流程、默认拉片能力与联网建议

用户进一步明确主流程为“大框架、角色交集、双方出招和节拍 → 作者确认 → 场景、章节 → 正文 → 局部修改”。技法降为场景可选建议和后台规则，不要求作者预先选择大量技法；既有技法数据和高级能力不删除。

拉片式能力应在后台每次生成时默认参与，关注景别、焦点、氛围、无台词动作、环境情绪以及动机驱动的动作与对话，最终输出小说文字。当前实施方向是把默认 `scene_direction` 指导放进现有写作请求，不新增每段规划模型调用；这一段登记的是需求与实施方向，尚待本轮测试确认。

主 agent 联网核对后，将用户提到的“15派”按其举例理解为 Save the Cat 十五拍，并建议用于整书结构参考，不把每章都套成十五拍。后续可以采用“故事骨架、场景交锋、画面情绪”三个关联视图，分别整理人物线与转折、目标和双方出招、微动作与环境情绪。它们是方案，尚不是已实现的新表格系统。

研究来源仅作概述和链接，不复制完整教材或示例：

- [Jessica Brody：小说十五拍入门资料](https://www.jessicabrody.com/wp-content/uploads/2020/01/Save_the_Cat_Writes_a_Novel_Starter_Kit_v6.pdf)。
- [K. M. Weiland：场景目标、冲突、结果与反应选择](https://www.helpingwritersbecomeauthors.com/how-to-write-scenes/)。
- [Film Education：景别、布景、身体表现与光线等术语](https://www.filmeducation.org.uk/resources/secondary/teaching_with_film/film_in_the_classroom/terminology/)。

本轮没有创建真实 `.xlsx` 文件、重型表格编辑器或十五拍专用编辑器。`docs/PRODUCT_PLAN.md` 已同步上述需求与建议；当前轮仍为进行中，等待实际接口、代码与验收结果。

任务与长任务的汇总形状已确认如下；单任务还提供包含 `call_id`、状态和阶段归属的 `usage_calls`，长任务累计所有 `job_ids`，包括失败与重试，避免只统计最后一次请求：

```json
{
  "usage": {
    "prompt_tokens": 0,
    "completion_tokens": 0,
    "total_tokens": 0,
    "estimated": false,
    "by_module": [
      {
        "module": "任务阶段",
        "provider": "服务类型",
        "model": "模型名称",
        "prompt_tokens": 0,
        "completion_tokens": 0,
        "total_tokens": 0,
        "estimated": false
      }
    ]
  }
}
```

上面的零值仅说明字段结构，不是某次真实模型调用的实测结果。

OpenAI 兼容流式响应中末尾的 usage 可以出现在空 `choices` 的事件中，断流时也可能没有最终统计；实现据此处理。Ollama 优先使用 `prompt_eval_count`、`eval_count`。为兼容现有服务商，没有强制添加 `stream_options`，所以部分服务即使正常结束也只能标记估算。依据：[OpenAI 流式事件](https://developers.openai.com/api/reference/resources/chat/subresources/completions/streaming-events)、[OpenAI 创建请求选项](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)、[Ollama Chat](https://docs.ollama.com/api/chat)。
