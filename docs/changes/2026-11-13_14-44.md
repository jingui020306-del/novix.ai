## 保护语义变更的理由与边界

### 技法进入对应请求

仅保留参考库无法落实作者对具体内容的使用要求。需要沿用现有技法数据和选择机制，将目标绑定的技法在调用时解析为最新保存内容，并送入相应的正文、故事或人物 AI 请求。

- 保留旧技法数据、已有选择和兼容的高级入口，不另建重复库。
- 技法作为写作或设定约束，不把它写成已经发生的故事事实，也不为使用技法新增一轮独立规划模型请求。
- 不修改既有任务阶段顺序与阶段含义。必要的材料准备在现有调用边界完成；改动位置、接口和兼容行为待代码确认后登记。

### 保存标记与生成前增量更新

用户已经确认“保存后标记变化、下一次生成前处理受影响材料”的时机。目的是让模型读取最新作者版，同时避免每次保存调用模型或每次生成重建全书。

- 保存不触发模型调用；保存后的变动应能标记相关派生材料需要更新。
- 下一次生成前，仅更新受影响的摘要与索引；未变化且不受影响的材料不重复生成或改写。
- 摘要、缓存、事件索引和关系索引是派生材料，不构成第二套权威来源。作者保存的卡片、正文和现有事实记录继续作为依据。
- 失效与更新不得覆盖作者正文或设定，不自动回滚，不清除历史；canon、session 和 patch 日志仍保持追加。
- 沿用现有项目主结构，不借增量更新更换存储环境、依赖或任务控制方式。实际影响依赖、标记位置与更新算法待实现确认，不能在文档中先编造。

### 技法与增量的实际契约

- 卡片选用存放在 `payload.writing_references: string[]`，章节沿用 `pinned_techniques` 与 `tool_skill_ids`。按当前故事、人物及实际使用的世界观/文风材料解析最新被选技法或工具，不把全库都塞入请求。
- `writing_reference_usage` 包含采用的 `references` 和未采用的 `omitted`；缺失、占位或超预算的参考提供省略原因。`CONTEXT_MANIFEST` 记录参考与 `memory_update`。
- 保存只记录哈希变化，不调用模型。生成前执行本地 `local_extractive` 摘要、变更章节片段与受影响世界材料更新；未变章的摘要和片段不重复改写。元数据哈希排除派生与运行字段，准备期间外部改源会中止并保留待更新标记。
- 初次没有状态时需要本地初始化；BM25 仍会重算本地语料统计。这不是 LLM 语义摘要，也不能据此声称实际 token 节省。

### 独立情节工作表的实际契约

- 使用 `cards/outline_planning_<storyId>.yaml`，卡片类型为 `outline`。实际 payload 为 `story_card_id`、`planning_worksheet: true`、`inspiration`、`beat_sheet_enabled`，以及四张实体表 `important_scenes`、`character_intersections`、`character_storylines`、`beat_sheet`。
- 此处 `important_scenes` 位于独立 outline 卡内，**不回写原故事卡的同名字段**。前文旧方案的 `planning_inspiration` 不是新表单的实际字段；新表单使用 `inspiration`。
- 十五节拍简表直接读取同一份 `beat_sheet` 的 `name`、`summary`、`chapter`、`emotion`，不另存一份简表数据。十五拍模板可选，启用可建立 15 行。
- `POST /api/projects/{project_id}/story-planning/propose` 接收 `story_card`、`planning_card`、四选一的 `table`，可选 `row`、`field`、`llm_profile_id`，以及 `mode: extract | suggest`。
- 返回 `rows: [{values, source_quotes, basis}]` 与 `writing_reference_usage`，只提供候选，不自动保存。默认 `extract` 只保留被作者原文连续引文与字段值支持的内容；无依据留空。`suggest` 由作者主动请求，未被原文支持的补充标为建议，不能伪造引用。未知字段、不存在的关联 ID、超限行等会拒绝，行或字段补全只处理空白。
- 生成与改写读取当前故事的独立 outline 规划卡，按当前或过去章选相关行，保留来源与省略数。章节材料和改写材料分别有 6500/4500 字符预算；整书节拍只用简短结构参考，关闭模板时不把全书节拍强制当作全局参考。
- `POST /api/projects/{project_id}/story-planning/export` 接收当前 `planning_card`，可带 `story_card`；返回真正的五工作表 `.xlsx`。导出当前未保存表单也不会写回卡片，详表和简表使用同源节拍。实现使用 Python 标准库，没有新增依赖。
- 世界观可选数据实际位于 `payload.extra_context`：`map_url`、`oc_notes`、`races[]`、`genders[]`、`levels[]`。地图是 URL 图片预览，不包含本地图片上传或视觉识图。
